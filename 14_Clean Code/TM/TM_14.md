**Soal**
Dari dua kode di bawah ini, mana yang kamu ingin cari masalahnya dan perbaiki di tengah-tengah malam, katakanlah jam 1 malam? Mengapa?
```
function processUser(user) {
  if (user) {
    if (user.isActive) {
      if (user.hasPermission) {
        return doSomething(user)
      }
    }
  }
  return null
}
function processUser(user) {
  if (!isValidCandidate(user)) return null;
  return doSomething(user);
}

function isValidCandidate(user) {
  return user && user.isActive && user.hasPermission;
}
```
## Jawaban
Untuk potongan koode pertama memiliki struktur nested if atau percabangan bertingkat yang membuat alur logika menjadi lebih sulit diikuti. Untuk memahami kapan fungsi doSomething() dijalankan, jadi si pembaca harus memeriksa setiap kondisi satu per satu dari luar ke dalam. Semakin banyak kondisi ditambahkan, semakin sulit proses debugging dilakukan.

untuk kode kedua itu dia gunain pendekatan abstraction dengan memindahkan proses validasi ke fungsi isValidCandidate(). Dengan cara ini, fungsi processUser() hanya bertanggung jawab terhadap alur utama proses, yaitu memeriksa apakah user valid lalu menjalankan proses berikutnya.

Kode kedua itu juga menerapkan prinsip Single Responsibility Principle (SRP) karena setiap fungsi memiliki tugas yang lebih spesifik:

processUser() → mengatur alur proses pengguna.
isValidCandidate() → memvalidasi apakah pengguna memenuhi syarat.

Refaktorisasi
```
function processUser(user) {
    if (!isValidCandidate(user)) {
        return null;
    }

    return doSomething(user);
}

function isValidCandidate(user) {
    return Boolean(
        user &&
        user.isActive &&
        user.hasPermission
    );
}
```
dari penerapan pendekatan ini, kode menjadi lebih mudah dipahami, proses debugging lebih cepat dilakukan, dan risiko kesalahan saat pengembangan maupun pemeliharaan sistem menjadi lebih kecil.
